# 0001 需求基线与范围裁决

- 状态:已确认
- 日期:2026-11-04
- 来源:drill 阶段逐分支裁决(用户逐条选定)
- 需求权威:帕金森患者肌肉保护微信小程序——功能说明书(docx)

## 背景

本仓原定位为「面向院内使用、医生开处方、姿态识别全量」。功能说明书提供了一套不同的需求基线:微信小程序 + 腾讯云开发、照护闭环、无姿态识别。经用户裁决以说明书为需求基线,再逐分支解决冲突。

## 决策

### 产品与范围

| 编号 | 决策 | 可检查句 |
| --- | --- | --- |
| D1 | 需求基线 = 功能说明书;与既有裁决冲突时以说明书为准,冲突处显式记账 | Given 说明书与既有产出冲突,When 产出引用需求,Then 以说明书为准且在产出内标出冲突点 |

| D6 | 说明书新增四类全入:风险预警、用药协同、Web 后台、宣教+离线+科研导出 | Given 自评疼痛≥4 分,When 提交,Then 弹窗+语音+推送+日志 |
| D7 | 文档交付物进范围;维护期与迭代承诺不进 | Given 首版验收,Then 三份文档在列,商务承诺不在 feature_list.json 内 |
| D8 | Android **手机 + 平板同一个 App**,响应式适配;iOS 只预留架构口,不在首版范围 | Given 同一账号在手机与平板登录,Then 功能清单一致,布局按屏幕宽度适配 |
| D9 | **手机为主设备、平板为兼容设备**;一设备长期绑定一患者 | Given 设备首次激活,When 绑定患者,Then 后续会话默认该患者 |
| D10 | 多机构,org_id 强制,管理员两级 | Given 管理员属机构 A,When 访问机构 B 患者,Then 403 并写审计 |
| D11 | H-Y 由康复治疗师确认;未确认时标记「疑似」,不得用于高风险训练准入 | Given 分期未经确认,When 生成方案,Then 高风险条目不可用 |
| D12 | Prescription 恢复,开具者 = 康复治疗师;系统自动匹配为基础方案,治疗师可增删条目与调整剂量 | Given 治疗师调整方案,Then 记录修改人与版本 |
| D13 | 打卡不做独立防作弊模型,只做训练有效性校验;异常记录标记「存疑」但不阻断打卡 | Given 一次训练的关键点可见率或动作幅度低于阈值,When 提交打卡,Then 记录标记「存疑」并可由治疗师查看,打卡仍成功 |
| D14 | 训练记录不只记打卡成功,还记动作错误次数、中断次数与有效帧占比 | Given 一次训练结束,When 写入 SessionRecord,Then 含完成次数、动作错误次数、中断次数、有效帧占比与存疑标记 |
| D15 | 仓库采用 monorepo:`apps/`(android、miniprogram、admin-web) + `services/`(api、cv-worker) + `packages/`(api-contract 与生成客户端)。契约是唯一共享真源,Android 只消费生成物,不手写跨端类型 | Given 契约字段变更,When 提交,Then 契约、后端与三端调用点可在同一提交内改完并通过 CI |
| D16 | 采用 **OWL 2 形式化本体 + SHACL 约束**,作为领域模型的上位语义层;本体与约束文件入版本控制,提交前须通过 SHACL 校验 | Given 新增或修改训练条目,When 提交,Then SHACL 校验通过且推理结果与预期一致 |
| D17 | 采集条件检查以脚部关键点可见度为门槛:踝/脚跟/脚尖任一平均可见度 <0.5 时拒绝启动动作识别并提示调整机位;训练条目视频构图底线为脚尖在画面内;上肢类条目可用半身构图,步态与下肢类必须全景 | Given 患者开始训练,When 踝/脚跟/脚尖可见度低于 0.5,Then 不启动动作识别并显示机位调整图示 |
| D18 | 多人同框的处置优先级:①**站位引导**——画面显示站位框,只跟踪框内主要人;②**人体跟踪**——检测框 + 位置连续性 + 外观特征做跨帧 ID;③**人脸匹配**仅在①②不足时启用,须单独同意、不建长期人脸库、用完即弃 | Given 画面出现多人,When 患者开始训练,Then 系统只跟踪站位框内的主要人;超出框或无法区分时不计数并提示调整站位 |

### 技术决策

| 编号 | 决策 |
| --- | --- |
| T1 | 平板 Kotlin + CameraX + MediaPipe Tasks(LIVE_STREAM)+ Media3 + Android TTS |
| T2 | 身份以内部主键为准,openid 仅作可撤销凭据;绑定码一次性、短时有效 |
| T3 | 离线视频按当前方案预缓存,720p,pinned + LRU;上限按机型分档(平板 1.5GB / 30 条,手机待实测后定) |
| T4 | 后端腾讯云标准栈:容器 API + PostgreSQL + COS + CDN + 微信适配器 |
| T5 | 云端 CV 推理服务:小程序上传训练视频,服务端跑 MediaPipe,结果异步回传;视频出设备须单独授权 |
| T6 | **待实测,未定案。** 候选:App 端 MediaPipe Pose Landmarker Full(1.2.2)/Lite;小程序云端同一 `.task` 的 Python 异步推理。备选:RTMPose(仅作云端高精度参考)。已排除:YOLO11-pose(AGPL-3.0)、MoveNet(17 点无脚跟/脚尖、2021 后停滞)、PP-TinyPose(2022-08 后停滞)。实测须同时覆盖低端手机与平板 |
| T7 | 每条训练记录携带模型版本、模型 SHA-256、指标算法版本与阈值配置版本 |
| T8 | 小程序用微信原生(TypeScript);管理端用 React + Vite;Android 用 Kotlin + Compose |
| T9 | 本体工具链:`rdflib`(解析)+ `pyshacl`(校验)+ 可选 Protégé/ROBOT(编辑与推理);OWL 2 用 Turtle 序列化 |

版本不一致的训练记录不得直接比较趋势;跨版本对比须显示版本差异提示。

## CV 实测清单(T6 定案前提)

### 算法层(PC + Python MediaPipe,无需平板)

| 项 | 方法 | 通过标准 |
| --- | --- | --- |
| 动作计数 | 四类动作各 10 组,与人工标注对比 | 组级 MAE ≤0.5 次;≥95% 组在 ±1 次内 |
| 步频 | 侧视步行视频,与人工计数对比 | 场次 MAE <3 步/分 |
| 步长(有标定) | 地面 1m 标记,与卷尺对比 | MAE <5cm |
| 姿势矫正角度 | 与测角器或人工标注对比 | 髋/膝 MAE ≤5°;踝 ≤10–15° |
| 小幅度动作 | 5°/10°/15° 动作检出率 | 满足临床要求的最小 ROM |

### 设备层(需目标 Android 平板)

| 项 | 方法 | 通过标准 |
| --- | --- | --- |
| 持续 FPS | Full/Lite 各跑 30 分钟 | p95 ≥15fps,不触发 SEVERE 热状态 |
| 端到端延迟 | CameraX 时间戳 → 反馈上屏 | p95 ≤300ms |
| 热降频 | 30 分钟连续推理 | 不明显掉帧 |
| 角度噪声 | 静态站立 60s | 大关节 ≤2–3°;踝 ≤5° |

### 已完成的实测(2026-11-04)

素材:《帕金森家庭康复训练操》,1080p / 25fps / 7 分 18 秒,户外固定机位。

| 项 | 结果 |
| --- | --- |
| 抽样检出率 | 95.7%(420/439 帧) |
| 平均关键点可见度 | 0.81 |
| 头/肩/肘/腕/手/髋 | 0.98–1.00 |
| 膝 | 0.77–0.83 |
| 踝 / 脚跟 / 脚尖 | 0.07–0.14 |

结论:该素材为半身构图,脚部在画面外。上肢动作计数与上半身姿势矫正可用;步态指标与下肢动作计数不可用。D17 的可见度门槛由此实测得出。

### 已确定的口径约束(不随实测改变)

- 步态不报绝对厘米,除非完成标定。
- 踝关节角度不作单次结论。
- 姿势矫正容差 ≥ 测量误差(大关节 ±5–10°,踝 ±10–15°)。
- 不用 `WorldLandmarks` 的 3D 坐标计算真实关节角(z 非度量)。

## 已评估未采用的技术方案

调研日期:2026-11-04。以下方案均不进入 MVP;排除不等于永久排除,条件变化时重新评估。

| 方案 | 类型 | 不采用的理由 | 重新考虑的条件 |
| --- | --- | --- | --- |
| VLX-Seek | 开放词汇定位 VLM,当前开源 10B | 输出区域框,无关键点,不能替代姿态估计;10B 需 Jetson 级设备;画面内目标检查用 MediaPipe 的 `visibility/presence` 已覆盖 | 需要开放词汇器械识别或多目标场景理解时 |
| SAM 3 | 概念分割 + 视频跟踪,473.6M / 3.45GB | 输出掩码与目标 ID,无关键点;RTX PRO 6000 约 2921ms/图,只能云端离线;作为 MediaPipe 前置分割的收益未验证 | 云端离线复核需要人体/器械精确分割,且实测证明能提升关键点质量时 |
