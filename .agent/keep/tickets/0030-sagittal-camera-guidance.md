# 矢状面动作的机位引导

## 现象

票 0021 记录的限制仍然成立：坐位伸膝、踏步、蹲起深度这些**矢状面**动作，从正面用 2D 关键点测不可靠——
膝关节屈伸、髋屈曲在图像平面上被"朝向镜头"压缩掉，患者摆对姿势也测不出幅度。
踏步与微蹲已改成"站立基线相对阈值"缓解比例问题，但机位本身没解决。

患者看不到任何提示，只会觉得"做了不计数"。

## 设计

**机位要求挂在 `ExerciseKind` 上，因为"哪个机位能测"由测量方式决定，不是动作的固有属性。**
这样不新增契约字段、不改管理端、不做迁移。

- 新增 `CameraView { FRONTAL, FORTY_FIVE, SAGITTAL }`（`core/pose`，纯 Kotlin）。
- `ExerciseKind.cameraView`：`MARCH`/`SEATED_LEG_RAISE` → `SAGITTAL`；`SQUAT` → `FORTY_FIVE`
  （深度要侧面，膝外翻要正面，折中）；`ARM_RAISE`/`POSTURE`/`STRETCH` → `FRONTAL`。
- 文案短（大字号下也不折行）：侧面「请侧身站立，让镜头拍到侧面」、45°「请身体转向 45°，介于正侧之间」。
- 展示：**复用训练页既有的 `statusText` 通道**，优先级低于距离提示（`framingHint` 优先），
  且只在**首次计数前**显示——患者摆好姿势做出第一个动作后自然消失，不需要新增可关闭状态。
- 正面机位 `hint == null`，链条原样落到「识别正常」，不改变现有表现。

## 不选"给条目加机位列"的理由

契约 + 管理端表单 + 数据库迁移 + 种子数据都要动，且每个动作的平面需要专业签核。
先按分析器类型给（改动 2 个文件 + 1 个测试），若将来同一分析器内正/侧都要，再升级为条目属性。

## 已知局限

- `kindFor` 是**标签启发式**：同一分类下正/侧混用靠标签兜底（如牵伸里的扩胸其实是正面）。
  标签识别不了时回退到分类，可能给出不合适的机位提示。
- 文案只引导、不校验：患者不照做也照样计数，只是测不准——与"不阻塞训练"的既有取舍一致。
- 真机复验待设备重连（与本轮其它精度改动相同）。

## 验收

- JVM 单测覆盖 `ExerciseKind.cameraView` 与文案非空/为空，以及 `kindFor` 对「坐位抬腿」「微蹲」「踏步」的映射。
- 全量 Android 单测不回归。
