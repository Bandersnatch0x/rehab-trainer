### 训练记录丢失与隔离（critical/high）

| 问题 | 修复 |
| --- | --- |
| 队列写入先删旧文件再 rename，失败即丢全部待传记录 | 先写临时文件，rename 失败才删旧文件并 `check`；补 `mkdirs` |
| 入队与补传并发读改写同一文件，互相覆盖 | `FileSessionUploadQueue` 全部操作加 `Mutex` |
| `AppData.submit` 用 Composable 作用域，退出页面会取消写入；异常可崩溃 | 新增应用级 `appScope` + `submitDetached`；写失败返回 false 并记日志，`CancellationException` 继续上抛 |
| 登出不清理待上传队列，换绑后旧患者记录用新 token 重放 | 队列接口加 `clear()`；`logout()` 调用 `AppData.clearPending()` |
| 无令牌时仍渲染旧快照并允许产生记录 | `needBind` 改为「无令牌即需绑定」 |
| 启动补传在未绑定/登出时也执行，401 把记录推进 30 分钟退避 | 仅在 `hasSession()` 时补传 |
| 有效帧占比的分母不含门禁帧，恒为 1.0 | `setTotalFrames` 在门禁分支前累计 |
| 0 次动作的组也记为已打卡，抬高连续天数 | `checkedIn = completionCount > 0` |
