# 归一化坐标的 x/y 单位混用（阈值随手机方向漂移）

## 现象

同一个姿势，手机竖着放和横着放给出不同判定。阈值名义上是一个数，实际有效值差 3.16 倍。

## 根因

MediaPipe 的归一化坐标是**各向异性**的：`x = x_px / 帧宽`、`y = y_px / 帧高`。
把「x 方向的差」除以「y 方向的高度」时，比值里混进了 `宽/高` 因子：

```
Δx_norm / Δy_norm = (Δx_px / W) / (Δy_px / H) = (Δx_px / Δy_px) · (H / W)
```

真正的物理比值是 `Δx_px / Δy_px`，所以现测值被乘上了 `H/W`。

## 受影响点位

| 位置 | 表达式 | 物理比 | 偏差因子 |
|---|---|---|---|
| `SquatAnalyzer.bottomIssues` 膝外翻 | `\|膝x − 踝x\| / torso` | `Δx_px / Δy_px` | `H/W` |
| `StretchAnalyzer` 抬臂幅度 | `(肩y − 腕y) / 肩宽x` | `Δy_px / Δx_px` | `W/H` |
| `StretchAnalyzer` 肩部倾斜 | `\|左肩y − 右肩y\| / 肩宽x` | 同上 | `W/H` |

竖屏 `W/H = 0.5625`、横屏 `W/H = 1.7778`（1280×720 一族），**同一姿势两者相差 3.16 倍**。

## 已修

- `PostureAnalyzer` 的 `lateralLean` / `headOffset`：x 差乘宽高比后再除以躯干高度，已与方向无关。见票 0029。

## 已修（2026-11-08）：阈值统一为物理比值

三处跨轴相除全部改为物理比值（x 差乘 `aspectRatio = 宽/高`，或除数乘同一因子）。
阈值**保持字面值不变**：`maxValgusRatio = 0.12`、`minRaiseRatio = 0.45`、
`maxShoulderTiltRatio = 0.25`、`maxRaiseAsymmetry = 0.75` 现在都是物理比值。

选择「统一为物理值」而非「以竖屏现状为准」的理由：这些整数当初就是按物理比写的
（0.12 ≈ 6.8° 是合理的临床阈值），竖屏折算值 0.0675 / 0.80 这类非整数不像设计意图。

### 患者可感知的变化（已确认接受）

改动不是纯重构，判定会变（以 720×1280 竖屏 / 1280×720 横屏为例）：

| 判定 | 触发方向 | 改前竖屏有效阈值 | 改前横屏有效阈值 | 改后（统一） |
|---|---|---|---|---|
| 膝外翻 `0.12` | 超过即异常 | 0.0675 | 0.213 | **0.12** |
| 肩部倾斜 `0.25` | 超过即异常 | 0.444 | 0.141 | **0.25** |
| 左右不对称 `0.75` | 超过即异常 | 1.333 | 0.422 | **0.75** |
| 抬臂幅度 `0.45` | 低于即异常 | 0.80 | 0.253 | **0.45** |

两端都收敛到名义值。注意「变严/变松」不能只看数值大小：超过即异常的判定，阈值
**变小**才是变严；抬臂幅度相反。因此竖屏下膝外翻更易触发、肩部倾斜与不对称更不易
触发、抬臂更难过关，横屏反之。

这是**患者可感知的判定变化**，已由项目负责人于 2026-11-08 确认接受。

### 仍未做

**真机两种握持方向的实际判定差异未录**。上表是几何推导值，`PoseAnalyzer` 里
MediaPipe 的实际关键点抖动、遮挡与构图偏差都未纳入。建议在能接真机的环境补录一次，
确认阈值 0.12 / 0.45 / 0.25 下的误报率可接受。

## 复现

```kotlin
// 像素空间造一个膝-踝水平偏移 = 0.10 × 躯干高度的深蹲，再按 1280×720 归一化
// 横屏：valgus = 0.10，竖屏：valgus = 0.178 —— 阈值 0.12 只在横屏下通过
```
