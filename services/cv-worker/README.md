# services/cv-worker

云端 CV 推理服务占位目录，**当前无代码，本轮明确不启动**（决策 D26）。

## 职责（按 T5）

小程序上传训练视频后，服务端异步推理并回传结果；小程序界面须明示「无实时反馈」。

## 启动前置（缺一不可）

1. **伦理与授权**：视频出设备需单独授权与伦理同意（人工硬门，见 `docs/delivery/acceptance-report.md`）。
2. **T6 定案**：模型与运行参数须先完成实测；未决项 11 明确「实测前不得视为已定」。
3. **未决项 8**：视频留存期限、脱敏策略与推理成本上限。
4. **未决项 9**：小程序端视频采集的时长/分辨率限制与上传失败兜底。
5. **契约先行**：当前契约没有上传凭证、任务状态、结果读取三类操作，须先补 `packages/api-contract/openapi.yaml`。

## 启动时的最小范围建议

先落一条端到端最薄的链路，验证通过再扩：

1. `POST /cv-jobs` 申请上传凭证（单次、短时、限定大小与类型）。
2. 客户端直传对象存储或经服务端中转（二选一，按成本与安全评审结论）。
3. `GET /cv-jobs/{id}` 返回任务状态（`queued` / `running` / `succeeded` / `failed`）。
4. `GET /cv-jobs/{id}/result` 返回与 App 同口径的姿态指标。
5. 失败与超时可重试，重试有上限；视频按留存策略过期清理。

## 明确的非目标

- 不做实时推理（那是 App 端职责）。
- 不做诊断结论输出。
- 不把步态绝对长度、m/s、摆动相百分比作为结果返回（D23：未标定前不可用）。
