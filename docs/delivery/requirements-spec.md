## 2. 项目背景与目标

### 2.1 背景

帕金森病患者需要长期、规律、训练量可控的居家运动训练，以维持肌肉力量、关节活动度、步态节律与姿势控制。居家训练同时存在三类风险：动作不适宜、训练过量、出现不适或跌倒时无人及时处置。本项目以“患者端训练 + 照护者协助 + 康复治疗师训练方案与随访 + 机构管理与科研聚合”为闭环，构建三端协同的肌肉保护训练系统。

### 2.2 产品目标

以下为产品目标形态；当前演示版的实际实现程度以第 6 节功能清单和验收报告为准。

1. **安全训练**：患者按治疗师下发的训练项目与训练量执行；训练页提供实时计数、节拍/语音提示、脚部入镜检查与紧急停止。
2. **照护闭环**：照护者可代为绑定、记录身体感受、查看训练记录与提醒；机构端可处置预警并登记随访。
3. **康复可控**：H-Y 分级由康复治疗师确认；训练方案由治疗师制定与调整；未确认分级不得开放高风险训练。
4. **科研数据底座**：本机构真实数据可做聚合画像与训练数据质量分析；小样本自动抑制，不输出行级患者数据。
5. **合规与可追溯**：机构隔离、审计日志、CSV 导出、二次验证与登录限流；演示数据明确标注。

### 2.3 本期定位

本期为**演示交付版**。Web 管理端与微信小程序的大部分查询/处置流程已接真实后端；Android 端以训练执行与适老化交互为主，首页、记录、提醒、档案为演示数据；云端异步视频分析、iOS、其他协同功能等不在本期范围。

## 3. 用户与角色

系统定义四类业务角色；机构管理员在本系统中对应“照护管理员”角色。所有写操作同时记录操作者（actor）与实际对象（subject），照护者代操作时两者不同。

| 角色 | 主要使用端 | 能做什么 | 不能做什么 |
| --- | --- | --- | --- |
| 患者 | Android App、微信小程序 | 查看本人训练安排、执行训练、记录身体感受、查看训练记录与提醒、查看正向训练统计 | 查看 H-Y 分级或症状标签；自行确认分级或修改训练方案；处置机构预警 |
| 照护者 | 微信小程序（代操作） | 用一次性绑定码绑定患者；代患者查看训练概览、记录身体感受、查看记录与提醒 | 确认分级、制定训练方案、处置机构预警 |
| 康复治疗师 | Web 管理端 | 确认 H-Y 分级；制定与调整训练方案；查看患者详情、训练记录、身体感受与评估；处置预警；查看随访台账、审计日志、科研数据；管理训练视频 | 跨机构访问；替代医生下诊断 |
| 照护管理员（机构管理员） | Web 管理端 | 新建患者档案；查看患者详情；处置预警；查看随访台账、审计日志、科研数据；管理训练视频；查看权限管理页（演示） | 确认 H-Y 分级；制定或调整训练方案；真实开通账号或变更权限 |

**角色边界说明**：系统业务角色为四类；机构管理员在本系统中对应“照护管理员”角色，机构内部可有两级管理范围，但不新增系统角色。H-Y 分级确认与训练方案制定权限仅属于康复治疗师；照护管理员/机构管理员看不到相应入口，直接访问会被拒绝并写审计。患者端不显示 H-Y 分级、症状名称、跌倒风险等级，只显示训练次数、连续坚持天数、完成率等正向指标。

## 4. 本期范围与不在本期范围

### 4.1 本期范围

- 三端载体：Android 手机与平板同一个 App（响应式）、微信原生小程序、Web 管理端。
- 后端：FastAPI + SQLAlchemy；开发/自检使用 SQLite，容器与生产目标为 PostgreSQL 17。
- 契约：`packages/api-contract/openapi.yaml`，21 个路径、25 个操作，作为三端唯一共享真源。
- 核心业务：登录与绑定、患者建档、H-Y 分级确认、训练条目、训练方案（多条目与乐观锁）、训练记录（批量幂等）、身体感受与评估、预警处置、随访台账、审计日志与 CSV、科研聚合、训练视频上传/上架/水印/署名/按分级下发。
- 专业预设：7 个量表 + 4 条预警规则的文献预设值已写入配置，但自动预警与风险分级开关保持关闭。
- 适老化：Android 大按钮、大字号、高对比度、语音/节拍、紧急停止；小程序患者端正向文案与静态对比度检查。

## 5. 核心业务流程

### 5.1 训练执行流程（Android）

1. 患者打开 App，进入首页或训练列表。
2. 选择可用训练条目；姿势矫正等高风险条目在分级未确认时显示“需治疗师确认分级”，不可进入。
3. 进入训练执行页，授予摄像头权限；按要求站入画面。
4. 需要全身构图的条目检查踝/脚跟/脚尖可见度；脚部不在画面内时冻结计数并提示调整站位，恢复后自动继续。
5. 训练页展示教学视频与实时画面（手机竖屏上下布局，平板横屏左右分栏；可切换纯实景+语音模式），保留实时计数叠加。
6. 患者可暂停/继续、完成本组；全部组完成后提示训练结束。
7. 出现头晕、胸闷、心慌、呼吸困难或跌倒时，使用“紧急停止”；该按钮在任何布局下保持可见。
8. 当前版本训练结束后**不写入记录、不上传机构端**；离开页面后本次计数不保留。

### 5.2 训练方案制定与调整流程（Web）

1. 治疗师进入患者详情，确认分级已由治疗师完成。
2. 进入训练方案编辑，逐条选择已发布且适用于当前分级的训练条目。
3. 每条独立填写组数、每组次数、BPM、每周频次；可添加/移除条目，至少保留一条，同一训练条目不得重复。
4. 保存时：无历史训练方案则新建 v1.0.0；已有训练方案用 `If-Match` 版本号做乐观锁更新，版本递增。
5. 另一端先更新时返回 409，页面提示版本冲突并载入最新版本，避免覆盖对方改动。
6. H-Y 5 级患者不允许制定训练方案；未确认分级时高风险条目不进入训练方案。

### 5.3 分级确认流程（Web）

1. 治疗师从患者列表或详情进入分级确认。
2. 选择 H-Y 1–5 级，填写康复评定与训练建议；预填文本仅为示例，确认前必须按实际评定改写。
3. 确认后患者分级状态变为“已确认”，高风险训练条目与训练准入随之开放。
4. 照护管理员看不到该入口；直接访问被拒绝并写审计。
5. H-Y 5 级只做宣教与转诊，不分配训练方案。

### 5.4 预警处置与随访流程（Web）

1. 机构人员进入预警中心，按全部/严重/警告/提示筛选。
2. 对“待处理”预警可执行：确认（已知悉）、登记随访、关闭。
3. 状态只能向前推进（例如 `open → acknowledged → followed_up → closed`，也允许从 `open` 直接登记随访或关闭）；已关闭为终态，不能回退。
4. 处理人与处置说明保存到服务端，刷新后保持；随访台账汇总状态为“已随访”或“已关闭”的记录。
5. 当前没有自动预警生成与真实通知投递；通知渠道仅持久化记录，不实际发送短信/电话/推送。

### 5.5 科研聚合流程（Web）

1. 治疗师或照护管理员进入科研数据页。
2. 查看本机构聚合画像：真实患者数、H-Y 分布、分级确认状态分布、年龄分段。
3. 查看训练数据质量：记录数、存疑比例、有效帧占比缺失率、有效帧占比分布、模型/指标算法/阈值配置版本分布。
4. 计数 1–4 的单元格抑制为“—”；比例为 1–4 的分子同样抑制；必要时二次抑制，避免由总数反推。计数为 0 按真值公布。
5. 只统计 `data_origin = real` 的患者，演示数据不计入；不提供行级患者数据下载或跨机构检索；每次访问写审计。

### 5.6 审计流程（Web）

1. 机构人员进入审计日志，按动作、资源类型、操作人、日期范围查询；筛选由服务端执行。
2. 表格显示时间、操作人、动作、资源、结果与详情 JSON。
3. 点击“导出 CSV”下载当前筛选结果，文件含 BOM，Excel 可直接打开；CSV 单元格做公式注入中和。
4. 只显示本机构事件；跨机构访问被拒绝的事件记在本机构名下；单次最多加载 1000 条，达到上限时禁止导出并提示缩小范围。

### 5.7 训练视频管理流程（Web）

1. 机构人员上传 MP4；服务端按文件头魔数校验真实类型，拒绝扩展名伪造与路径穿越。
2. 上传结果为草稿；填写关联训练条目、适用 H-Y 分级、水印文字、来源署名与备注。
3. 确认后执行“上架”；未设置适用分级时上架被拒绝。
4. 已上架且分级匹配的视频才会下发给患者；水印与署名由客户端叠加显示，不烧录进视频文件。
5. 可下架（retired），下架后不再下发，文件与记录保留；上下架写审计。
6. 当前使用本地媒体静态根，未接对象存储、签名 URL 或 CDN；生产部署需另行配置。

## 7. 数据、隐私与合规

### 7.1 数据范围与标识

| 数据类别 | 内容 | 保护要求 |
| --- | --- | --- |
| 患者身份 | 姓名、出生年份、机构、绑定关系 | 按机构隔离；患者端不显示分级或症状标签；科研不返回出生年份原值 |
| 康复评估 | H-Y 分级、量表记录、身体感受 | 仅治疗师/照护管理员在机构端可见；评估只记事实，不输出风险分级 |
| 训练记录 | 完成次数、动作错误、中断、有效帧占比、存疑、版本 | 机构隔离；跨版本不可直接比较趋势 |
| 训练视频 | 教学视频、水印、署名、适用分级 | 上传需机构权限；水印/署名客户端叠加；当前本地存储，未接对象存储 |
| 审计事件 | 操作人、动作、资源、结果、详情 | 本机构可见；跨机构拒绝事件也记录；CSV 导出受权限与条数限制 |

### 7.2 机构隔离

- 所有资源访问按调用者 `org_id` 强制隔离；跨机构访问返回 403 并写审计。
- 管理端不提供跨机构切换或检索。
- 患者与照护者只能看到自己关联的患者；照护者代操作时同时记录 actor 与 subject。

### 7.3 演示数据标注

- 演示版中未决项与待签核内容使用 mock 数据，页面明确标注“演示数据”。
- Android 首页、训练记录、提醒、患者档案为演示数据；Android 训练执行页的条目/训练量为内置演示条目。
- 小程序演示登录入口在 `DEMO_LOGIN_ENABLED=true` 时包含演示账号凭据；生产构建必须关闭该开关并移除演示账号。
- 科研聚合只统计 `data_origin = real`，演示数据不计入。

### 7.4 科研小样本抑制

- 计数 1–4 的单元格抑制为 `count: null` 且 `suppressed: true`，页面显示“—”，不显示 0。
- 计数为 0 按真值公布，因为 0 不指向任何个体。
- 若某分布只隐藏 1 个单元格且总数已公开，再抑制一个最小可见单元格（二次抑制），防止由总数相减反推。
- 分子 1–4 的比例同样抑制；不提供插值、区间或取整。
- 不提供行级患者数据下载、跨机构检索或出生年份原值。

### 7.5 审计与访问控制

- 登录支持 JWT、刷新令牌、登录限流与 TOTP 二次验证；TOTP 启用需运维操作，无自助页面。
- 审计记录操作人、动作、资源、结果、详情与时间；管理端可筛选并导出 CSV。
- CSV 导出对以 `= + - @` 等开头的单元格做公式注入中和，并加 BOM 便于 Excel 打开。
- 媒体上传按文件头魔数校验 MP4，文件名由服务端生成，拒绝路径穿越；单文件超限返回 413。
- 当前未做等保测评、医疗器械注册或伦理审查；不得用于康复诊断或真实患者监护。

### 7.6 步态指标边界

- 在完成地面标定与人工足部接触标注前，步态指标不进入训练成绩。
- 不报绝对厘米或米每秒、不报摆动相百分比、不由分窗不稳推断 RAS 适用性。
- 检出率、关键点可见度与缺失时间段只用于采集质量提示。
- 踝关节角度不作单次结论；姿势矫正容差 ≥ 测量误差（大关节 ±5–10°，踝 ±10–15°）。
- 不使用 `WorldLandmarks` 的 3D 坐标计算真实关节角（z 非度量）。

### 9.3 安全底线

- 训练中出现头晕、胸闷、心慌、呼吸困难或跌倒：立即停止训练，使用紧急停止，联系治疗师或拨打急救电话。
- 绝对停止（按急症处理）：胸痛/胸闷或放射痛伴出汗恶心；严重呼吸困难；眩晕/濒晕/失衡；新发意识模糊、言语不清、单侧无力或视力突变；心悸/不规则心跳；冷汗、苍白、发绀、意识丧失；跌倒伴头部撞击或受伤。
- 相对停止（休息后评估）：中度气短、疲劳、腿抽筋、关节/肌肉疼痛；RPE ≥17；站立时头晕/眼前发黑；冻结发作经提示仍不缓解。
- 系统不输出诊断、分级结论或风险分级；H-Y 5 级仅宣教与转诊。

### 12.1 术语表

| 术语 | 含义 |
| --- | --- |
| H-Y | Hoehn & Yahr 分级，用于帕金森病运动症状分级；由康复治疗师确认。 |
| RAS | Rhythmic Auditory Stimulation，节律性听觉刺激；本系统以节拍/语音辅助步态训练。 |
| BPM | 本系统指“步/分”（steps/min），一拍一步；不是音乐 BPM。 |
| 有效帧占比 | 训练视频中可用于姿态识别的帧占比；低于占位阈值时标记“存疑”。 |
| 存疑 | 训练数据质量待核实，不阻断打卡，不作为诊断依据。 |
| 小样本抑制 | 计数 1–4 的聚合单元格不显示，页面以“—”代替，防止反推个人。 |
| 演示数据 | 界面占位数据，不代表真实患者或真实训练结果。 |
| TOTP | 基于时间的一次性验证码，用于管理端二次验证。 |
| actor / subject | 执行操作的人 / 操作所指向的患者；代操作时两者不同。 |
