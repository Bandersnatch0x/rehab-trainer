# 真机复验清单

设备连上后按本单逐项跑，一次跑完。写这份单子的原因：几笔 Android 改动目前**只有 JVM 单测证据**，
而 JVM 测不到 MediaPipe 与摄像头路径；散在各票里的「待真机复验」没有可执行口径，设备到了还得临场想。

**一条纪律**：结论要贴原始证据（日志行、截图路径、后端查询结果），不要只写「正常」。
合成用例骗过一次人了——那次的教训是夹具与被测假设同源，所以这里每一项都要求外部可核对的东西。

## 前置

```powershell
adb devices                                   # 确认设备在线
adb install -r apps/android/app/build/outputs/apk/debug/app-debug.apk
adb logcat -c; adb logcat -s PoseAnalyzer     # 姿态管线每秒一行，见下
```

每秒日志形如（`secondPerson`、`cameraRoll`、`fps`、`detect` 是这一轮为复验加的）：

```
pose: shoulder=0.98 wrist=0.91 hip=0.99 ankle=0.77 width=0.31 wristRaise=0.42 hipAnkle=1.02 secondPerson=false cameraRoll=-12.3 fps=29.9 detect=14.8
```

后端要可达（本机 API + 数据库，见 `docs/deployment/README.md`），否则 D4 无法验。
`cameraRoll` 与 `detect` 是本次专门加的字段：没有它们，D1 与 D2 的帧率只能靠感觉。

---

## D1 相机横滚补偿（票 0029）

**要证明的**：手机斜放时不再被读成「患者躯干侧倾」。

1. 患者站直不动，手机水平放置，记 3 行日志的 `cameraRoll`。
2. 把手机一侧垫高约 10°，再约 20°，各记 3 行。

**判定**
- `cameraRoll` 随倾角单调变化，且与目测角度同量级（±5° 以内）；水平时接近 0。
- 训练页**不出现**「调整：躯干侧倾」；踏步/抬腿每组不被判为不达标（对比 `GET /sessions` 里的 `movementErrorCount`）。

**预期内的边界**：垫高超过 20° 时 `cameraRoll` 会打回 0（上限保护，更可能是躺姿或极端机位），
此时误报侧倾可能重新出现。**这是设计不是 bug**，记下当时的实际倾角即可。

**失败时**：把原始日志行、目测倾角、`movementErrorCount` 一起回填票 0029。

---

## D2 第二人入镜冻结（票 0033）

**要证明的**：护理员入镜时计数冻结并提示；顺带量出 `setNumPoses(2)` 的帧率代价。

1. 患者单独在画面，记 `secondPerson=false` 与 `fps` / `detect`。
2. 第二人走进画面（露头肩即可）→ 记 `secondPerson=true` 那几行。
3. 第二人离开 → 观察是否自动恢复。

**判定**
- 第二人在画面时：计数冻结、状态栏显示「画面内有多人／请确保只有患者入镜」、红色告警框出现。
- 第二人离开后自动恢复计数，不需要重进页面。
- 幽灵不误触发：单独一人正常训练时 `secondPerson` 应为 `false`，不应反复跳 `true`。

**帧率**：把 `detect`（MediaPipe 每秒回多少次结果）记下来。
两台设备（一台低端、一台中端）各记一次；若 `detect` 低到动作反馈明显滞后，回填票 0033 重新评估 `numPoses=2`。

**失败时**：贴 `fps` / `detect` 数值、设备型号与系统版本。

## D3 幅度校准持久化（票 0028）

**要证明的**：第二次训练起第一次动作就计数，不再重复「前 2 次不计数」。

1. 同一患者、同一条目连做两组训练。第一组：观察前 2 次动作是否显示「校准中：还需完成 N 次动作」。
2. 退出训练页再进入，做第一次动作。

**判定**
- 第二组**第一次动作就计数**，不再出现「校准中」。
- 本地文件存在：`adb shell run-as com.rehabtrainer.app ls -l files/calibration`
- 换一个患者（或换条目）后仍会校准——键是「患者 + 条目」，不该串。

**弱验证（标注即可）**：「存下的幅度不合身时丢弃重练」不好在现场构造；
可临时删掉 `amplitude-calibration.json` 验证「无存值时退回重新校准」。

## D4 四页真实数据与上传闭环（P3-1）

**要证明的**：首页/记录/提醒/档案读的是后端；训练记录每组写入并上传，断网留队补传。

1. 绑定患者后依次打开四页，各截图；与后端数据核对 1–2 条（`GET /patients`、`GET /sessions`、`GET /alerts`）。
2. 停掉 API（或断网），完成一组训练 → 进训练记录页，记「待上传」条数。
3. 恢复 API → 再次进记录页，观察是否自动补传。

**判定**
- 四页数据与后端一致，不是演示数据。
- 断网期间记录留队且条数可见；恢复后条数归零，后端 `GET /sessions?patientId=` 能查到该条。
- 同一条记录重复补传不会产生两条（`clientRecordId` 幂等）。

## D5 单位混用取证（票 0031，**只取证，不改码**）

**要证明的**：膝外翻 / 牵伸幅度 / 肩部倾斜三处阈值随握持方向漂移（竖屏与横屏有效值差 3.16 倍）。

同一患者、同一动作、同一姿势，**竖屏与横屏各录一段**，每段完成 ≥5 次，记下每次的达标/不达标与提示语。

**这不是通过/失败项**，是给治疗师签核用的证据：修它会改变患者看到的判定。
**不要在复验里顺手改这三处阈值**，也不要在同一轮里改完再验——那样分不清差异来自哪。

---

## D6 回归（这些不该被本轮改动破坏）

- 脚部出框时计数冻结并提示，脚部回到画面后自动恢复（D17）。
- 暂停/继续、旋转后仍保持暂停。
- 紧急停止在手机竖屏、手机横屏、平板三种布局下都可见可点（≥80dp）。
- 200% 字体下状态栏与告警框不重叠。
- 训练页**不出现**「请侧身站立」之类机位提示——票 0030 已撤回，若出现说明有回退。
